# arXiv Digest

Сервис по расписанию:

1. собирает свежие препринты с arxiv.org по заданным темам (поисковые запросы arXiv и категории);
2. суммаризирует полный текст каждой статьи локальной LLM через OpenAI-совместимый API;
3. собирает PDF-дайджест на русском языке;
4. рассылает его по списку email-адресов.

Управление — через панель администратора: темы, получатели, расписания, настройки SMTP, ручные запуски с логами, статьи, дайджесты.

## Быстрый старт

Нужны Docker с Compose v2 и запущенная локальная модель с OpenAI-совместимым API (vLLM, Ollama, LM Studio и т.п.).

```bash
cp .env.example .env        # затем задайте секреты и параметры LLM, см. ниже
docker compose up -d --build
docker compose ps           # все сервисы должны стать healthy
```

- Панель администратора: <http://localhost:8080> — логин и пароль из `ADMIN_USERNAME` / `ADMIN_PASSWORD`.
- Документация API (OpenAPI): <http://localhost:8080/api/docs>.

Дальше в панели:

1. **Темы** — добавьте тему: поисковые запросы и, при желании, категории arXiv (см. [«Как писать поисковые запросы»](#как-писать-поисковые-запросы)). При первом старте темы берутся из `seed_topics.yaml`.
2. **Получатели** — добавьте адреса.
3. **Настройки SMTP** — заполните параметры сервера и отправьте тестовое письмо.
4. **Расписания** — создайте расписание для задачи «Полный пайплайн».
5. **Дашборд → «Запустить пайплайн сейчас»** — проверьте всё вручную; ход выполнения и логи видны на странице запуска.

## Настройка `.env`

Все секреты задаются только переменными окружения. Файл `.env` в git не попадает.

| Переменная | Назначение |
|---|---|
| `SECRET_KEY` | Подпись JWT. Длинная случайная строка: `openssl rand -hex 32` |
| `ADMIN_USERNAME`, `ADMIN_PASSWORD` | Админ создаётся при первом старте, если такого пользователя ещё нет. Позже пароль меняется в панели (меню пользователя) |
| `POSTGRES_*`, `RABBITMQ_*` | Доступы к БД и брокеру. Меняйте пароли до первого запуска: они записываются в тома при инициализации |
| `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY` | Адрес, имя модели и ключ OpenAI-совместимого API |
| `LLM_CONTEXT_CHARS` | Размер чанка текста статьи в символах. Должен помещаться в контекст модели вместе с ответом (примерно 4 символа на токен) |
| `LLM_MAX_TOKENS`, `LLM_TEMPERATURE`, `LLM_TIMEOUT_SECONDS` | Параметры одного запроса к модели |
| `LLM_CONCURRENCY` | Число параллельных суммаризаций (процессы воркера очереди `llm`) |
| `LLM_EXTRA_BODY` | JSON с дополнительными полями запроса, например для отключения reasoning |
| `SMTP_PASSWORD` | Пароль SMTP. Остальные параметры SMTP задаются в панели и хранятся в БД |
| `ARXIV_REQUEST_DELAY_SECONDS` | Пауза между запросами к arXiv. Не ставьте меньше 3 секунд |
| `ARXIV_MAX_RESULTS_PER_TOPIC` | Максимум статей на тему за один сбор (на все запросы темы вместе) |
| `ARXIV_USER_AGENT` | User-Agent с контактным адресом — этого просит arXiv |
| `SEND_EMPTY_DIGEST` | Рассылать ли дайджест, в котором нет статей (по умолчанию нет) |
| `PIPELINE_STALE_HOURS` | Через сколько часов без активности запуск считается зависшим |
| `TZ` | Таймзона, в которой панель и PDF показывают даты. В БД всё хранится в UTC |
| `LOG_LEVEL`, `LOG_FORMAT` | Уровень и формат логов: `json` или `console` |
| `DATA_DIR` | Каталог в контейнере для PDF статей, дайджестов и лог-файлов (том `data`) |
| `SEED_TOPICS_PATH` | Путь в контейнере к YAML с начальными темами (по умолчанию `/seed/seed_topics.yaml`) |

Комментарий в `.env` на одной строке со значением должен отделяться от него пробелом: `TZ=Europe/Moscow  # комментарий`. Без пробела `#…` станет частью значения.

При старте конфигурация проверяется: если обязательная переменная не задана, сервис завершится с сообщением, какой именно не хватает.

## Как писать поисковые запросы

Тема — это список поисковых запросов в синтаксисе arXiv API и, при желании, категории. Каждый запрос выполняется отдельно; статья попадает в тему, если её нашёл любой из них. Какие именно запросы сработали, видно в карточке статьи.

| Элемент | Что значит |
|---|---|
| `ti:` `abs:` `all:` `au:` `cat:` `co:` | Поле: заголовок, аннотация, все поля, автор, категория, комментарий |
| `AND` `OR` `ANDNOT` | Операторы, только заглавными. `and` и `or` строчными не работают — редактор об этом предупредит |
| `( ... )` | Группировка |
| `"..."` | Точная фраза |

Строка без префиксов и операторов считается фразой: `autonomous ship` сохранится как `all:"autonomous ship"`. Внутри выражения у каждого слова или фразы должен быть префикс поля.

Примеры:

```text
all:"operational design domain"
(ti:dataset OR ti:benchmark) AND (all:railway OR all:rail)
abs:ODD AND (abs:autonomous OR abs:automated OR abs:"self-driving")
all:"safety case" ANDNOT cat:cs.CL
```

Что стоит помнить:

- arXiv ищет только по заголовку, аннотации и метаданным, а не по полному тексту. Узкий маркер вроде номера стандарта чаще всего ничего не найдёт.
- Короткие термины (`ODD`, `ATO`) шумят: сочетайте их с контекстом через `AND`.
- Если у темы заданы категории, они добавляются к каждому запросу: `(<запрос>) AND (cat:cs.RO OR cat:cs.CV)`. Период сбора добавляется автоматически.
- `ARXIV_MAX_RESULTS_PER_TOPIC` ограничивает тему целиком, а не каждый запрос. Запросы идут по порядку, поэтому самые важные ставьте первыми.
- Между запросами к arXiv выдерживается пауза, так что тема из 20 запросов собирается около минуты.

В редакторе темы запрос проверяется на лету: под полем видно, в каком виде он сохранится, ошибки и предупреждения. Кнопка «Проверить за N дней» показывает, сколько статей находит каждый запрос, с примерами — так видно запросы, которые не находят ничего или находят слишком много.

### Импорт, экспорт и начальные темы

На странице «Темы» есть «Экспорт YAML» и «Импорт YAML». Импорт сначала показывает, что изменится, и только потом применяется. Режим «Объединить» обновляет темы с тем же названием и добавляет новые; «Заменить все» дополнительно удаляет темы, которых нет в файле. Если в файле есть хотя бы одна ошибка, не записывается ничего.

```yaml
topics:
  - name: "Датасеты для железной дороги"
    description: "Новые датасеты и бенчмарки"
    categories: ["cs.CV", "cs.RO"]
    is_active: true
    queries:
      - '(ti:dataset OR ti:benchmark) AND (all:railway OR all:rail)'
      - autonomous train
```

При старте, пока в базе нет ни одной темы, они импортируются из `seed_topics.yaml` в корне репозитория (файл смонтирован в контейнер `backend`). Позже файл не перечитывается: меняйте темы в панели или через импорт.

То же доступно через API (`/api/docs`): `POST /api/topics/validate-query`, `POST /api/topics/preview`, `GET /api/topics/export`, `POST /api/topics/import?mode=merge&dry_run=true`.

## Подключение локальной LLM

Контейнеры обращаются к модели на хосте по имени `host.docker.internal`.

**Ollama**

```bash
# сервер должен слушать не только localhost и иметь достаточный контекст
OLLAMA_HOST=0.0.0.0:11434 OLLAMA_CONTEXT_LENGTH=16384 ollama serve
```

```dotenv
LLM_BASE_URL=http://host.docker.internal:11434/v1
LLM_MODEL=qwen3.5:9b
LLM_EXTRA_BODY={"reasoning_effort":"none"}
```

**vLLM**

```bash
vllm serve Qwen/Qwen2.5-14B-Instruct --port 8000 --max-model-len 16384
```

```dotenv
LLM_BASE_URL=http://host.docker.internal:8000/v1
LLM_MODEL=Qwen/Qwen2.5-14B-Instruct
```

**LM Studio** — включите Local Server и укажите `LLM_BASE_URL=http://host.docker.internal:1234/v1`.

После изменения `.env` пересоздайте контейнеры: `docker compose up -d`. Состояние модели видно на дашборде и в `GET /api/llm/health`.

Суммаризация устроена как map-reduce: текст режется на чанки по `LLM_CONTEXT_CHARS`, каждый чанк сжимается в конспект, из конспектов собирается итоговое резюме. Промпты лежат в `backend/app/services/prompts.py`.

## Как это работает

| Сервис | Что делает |
|---|---|
| `backend` | FastAPI: REST API и миграции БД при старте |
| `worker` | Celery, очереди `default` (сбор, PDF, тик планировщика) и `mail` (рассылка) |
| `worker-llm` | Celery, очередь `llm` — суммаризация |
| `beat` | Celery Beat: раз в минуту ставит задачу `scheduler.tick`. Должен работать в одном экземпляре |
| `frontend` | nginx: панель администратора и прокси `/api` → `backend` |
| `postgres`, `rabbitmq` | БД и брокер |

Шаги пайплайна — `collect`, `summarize`, `build_digest`, `send_digest` — можно запускать по отдельности и повторно. `full_pipeline` выполняет их цепочкой. Если пайплайн уже идёт, новый запуск создаётся со статусом «Пропущен».

По умолчанию обрабатываются прошедшие сутки по UTC: запуск 7 октября собирает статьи за 6 октября. В выходные arXiv не публикует новые статьи — тогда сбор завершается успешно с нулём найденных, а дайджест получает статус «Пустой» и не рассылается.

## Отладка

```bash
docker compose --profile debug up -d   # дополнительно Flower и Mailpit
```

- **Mailpit** — локальный SMTP-сервер с веб-интерфейсом: <http://localhost:8025>. В настройках SMTP укажите сервер `mailpit`, порт `1025`, шифрование «Без шифрования», логин пустой.
- **Flower** — мониторинг Celery: <http://localhost:5555>.

Логи:

```bash
docker compose logs -f worker worker-llm   # JSON-логи сервисов
```

Логи конкретного запуска удобнее смотреть в панели: «Запуски» → запуск → блок «Логи». Они же доступны через `GET /api/runs/{id}/logs`, а файлы с ротацией лежат в томе `data` (`/data/logs`).

## Типовые проблемы

**Запуск суммаризации падает с «LLM недоступна».** Модель не запущена или неверен `LLM_BASE_URL`. Проверьте с хоста: `curl http://localhost:11434/v1/models`. Сервер модели должен слушать `0.0.0.0`, а не только `127.0.0.1`. На Linux убедитесь, что порт модели открыт для сети Docker. Статьи такого запуска получают статус «Ошибка» — после починки запустите шаг «Суммаризация» с галочкой «Повторить и для статей, у которых суммаризация раньше не удалась».

**Резюме обрывочные или про «начало статьи».** Контекст модели меньше чанка. У Ollama контекст по умолчанию маленький — задайте `OLLAMA_CONTEXT_LENGTH` или уменьшите `LLM_CONTEXT_CHARS`.

**Ошибка «Модель дважды вернула некорректный ответ: ответ пустой».** Обычно reasoning-модель тратит весь `LLM_MAX_TOKENS` на размышления. Отключите их через `LLM_EXTRA_BODY` или увеличьте `LLM_MAX_TOKENS`.

**Сбор нашёл 0 статей.** Проверьте, что тема активна, а период — не выходные. Запрос к arXiv виден в логах запуска (`collect_topic_started`), его можно выполнить вручную в браузере.

**arXiv отвечает 429 или 503.** Сервис повторяет запросы с нарастающей паузой, а затем повторяет весь шаг. Не уменьшайте `ARXIV_REQUEST_DELAY_SECONDS`.

**Письма не уходят.** Проверьте настройки кнопкой «Отправить тестовое письмо» — в ошибке будет ответ сервера. Для порта 465 выбирайте «SSL / TLS», для 587 — «STARTTLS». Если задан логин, в `.env` должен быть `SMTP_PASSWORD`.

**Дайджест не разослан повторно.** Так и задумано: получателю, которому дайджест уже доставлен, он второй раз не уходит. Чтобы отправить всем заново — «Дайджесты» → «Отправить повторно» → «Всем активным получателям».

**Запуск висит в статусе «Выполняется».** Если воркер был убит, запуск будет помечен ошибкой через `PIPELINE_STALE_HOURS` часов без активности. Раньше его можно отменить кнопкой на странице запуска.

**Порт 8080 занят.** Поменяйте проброс порта у сервиса `frontend` в `docker-compose.yml`.

**Изменили пароль БД или RabbitMQ в `.env`, и сервисы не подключаются.** Пароли записываются в тома при первом запуске. Либо верните прежние, либо пересоздайте тома: `docker compose down -v` (данные будут удалены).
